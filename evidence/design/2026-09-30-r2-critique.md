# Paperloft Receipts: design critique, second review (after fixes), 2026-09-30

Reviewer: critic (Mac design lead role). Reviewed against the macOS Human Interface Guidelines and the six-line rubric. This is the second review. The first review is `evidence/design/2026-09-30-critique.md`. I scored what I saw today, independently of the first review's scores.

Build: QA build `build/QADerivedData/Build/Products/QA/Paperloft Receipts.app` (bundle id `app.paperloft.receipts`, version 1.1 (1), checkout at `744104e`).
Method: I looked only at the running app, using background computer-use tools (screenshots, AX tree, clicks, background keystrokes and menu commands). I did not read any source code or tests. GUI lock `~/Factory/.gui.lock` held as `critic2` from 23:35Z until the end of the session.

- Launch A (first launch): `-PaperloftQAProfile critic2-onboarding -PaperloftStoreMock YES`
- Launch B (populated): `-PaperloftUITestMode YES -PaperloftModel stub -PaperloftStoreMock YES`. File had no "Load Development Receipts" item. The profile already held a sample library: 4 Inbox items (all flagged "Issue") and 1 filed receipt. In this profile I confirmed one item (04-software), undid that filing from History, removed one item (05-utilities), and deleted then restored the filed receipt.
- Appearance was switched with the app's own Settings › General › Theme control. The Mac's system appearance is Light. Theme was left on **System**.
- Two `app_batch` calls were aborted by a user interrupt partway through the dark-mode pass. I carried on with single calls, and nothing was left half-done.

Scores: 5 excellent, 4 good, 3 needs work, 2 poor, 1 broken. Every score below 4 has a fix.

## 1. Top findings (fix these first)

**The fixes landed.** The P1 theme bug is gone: Dark → System now redraws every window correctly, in both profiles and both repro paths. The Settings "Turn On" error is gone. The export sheet's premature validation, layout jumps and Q1 default are fixed. The Library now has aligned columns, localized dates, "$12.50", a visible selection and correct plurals. Import and Paste are toolbar items. There is a Receipt menu, plus Edit › Find (⌘F) and File › Export for Accountant… (⇧⌘E). The Settings window sizes to each tab, shows the library by name and uses a real category List.

What still needs work, in priority order:

1. **P1: Undo from History makes the receipt disappear.** After filing 04-software and pressing Undo in History, the row changes to "Undone". The receipt then appears in neither the Library nor the Inbox (Inbox stays at 3). Nothing tells the user where it went. Evidence: `29-history-after-undo-light.jpg`, `29b-inbox-after-undo-item-missing.jpg`, `29c-library-after-undo-item-missing.jpg`. Fix: Undo should put the document back in the Inbox, selected and ready to edit. Change the History row to "Returned to Inbox" with a "Show in Inbox" button. This matches what Help promises ("Every filing can be undone").
2. **P1: Remove from Inbox is silent and can't be undone.** Remove takes the item away immediately. There's no confirmation, no feedback, no Edit › Undo entry (Edit only offers "Undo Last Filing"), and it doesn't go to Recently Deleted. Help says Remove "sets a document aside", but there's no place to find set-aside documents. Evidence: `35-review-after-remove-no-feedback.jpg`, `36-recently-deleted-after-inbox-remove-empty.jpg`, `41-help-bottom-light.jpg`. Fix: register the removal with the window's `UndoManager` ("Undo Remove from Inbox", ⌘Z). Show a transient banner under the toolbar ("Removed 05-utilities.pdf · Undo"). Either send removed items to Recently Deleted or change the Help text to say what really happens.
3. **No feedback after Confirm, and the selection jumps to the top.** Confirming 04-software removed it from the list and selected 02-meal (the first row) instead of 05-utilities (the next row). There was no confirmation of where the document was filed (`24-review-after-confirm-no-feedback.jpg`). Fix: show a banner "Filed to 2026/Office supplies · Undo" for about 4 s, and select the next row in list order, as Mail does after archiving.
4. **Inbox keyboard focus still jumps to Vendor.** After one ↓ in the list, focus moves into the Vendor field, so the next ↓/↑ moves the text caret instead of the selection (`22-review-keyboard-focus-jumps-to-vendor.jpg`). Receipt › Next/Previous Document (⌘] / ⌘[) now work, which softens this, but plain arrow keys in a list must keep the focus in the list.
5. **Review screen content.** The page heading is still the tagline "A place for your paperwork". List rows still show only the file name and a generic "Issue" badge. The date is an ISO text field with a custom calendar button. The total is an unformatted "12.50". Quick Look still shows the internal name "payload.pdf" (`23b-review-quicklook-title-zoom.jpg`).
6. **Main-window chrome is still custom.** The opaque green sidebar has a serif wordmark, a gray circle holds the sidebar toggle, and a duplicate Settings page sits in the sidebar. There's no Go menu for Inbox / Library / History.
7. **Library is still a custom card list, not a `Table`.** Search sits in the content area instead of the toolbar. There's a per-row "View" button. The no-results and empty-library states reuse "No matching documents… adjust your search and filters".
8. **Copy consistency.** The export now has three names: "Tax & Accountant Export…" (button, sheet), "Export for Accountant…" (File menu) and "Accountant pack" (Help, Shortcuts). "Receipts" and "documents" are still mixed on the same screens. Menu items now use "…", but button titles still use ASCII "...".
9. **Icon: unchanged since the first review.** The `.icns` is byte-identical, and the Icon Composer layers, colours and stacks in `Assets.car` have identical digests. The tray body is still 1.18:1 against the tile at 16 and 32 px. The pending proposal in PROPOSALS.md still applies, so I didn't add a new one (section 5).

## 5. Icon review

**Sources compared**
- Owner artwork: `design/app-icon-source.png` (1254×1254): a cream receipt with two text bars and a zig-zag tear in a green tray with a U-notch, on deep green.
- Built icon: `Contents/Resources/AppIcon.icns` and `Assets.car`.

**Did the build change?** No.
- `AppIcon.icns` is byte-identical to the first-review build (SHA-1 `9595d53b…`), and its extracted 16/32/128/256 renditions match the first review's `built_*.png` pixel for pixel.
- In `Assets.car` (`assetutil --info`), the Icon Composer layers `01-tray-back`, `02-receipt`, `03-fold` and `04-tray-front`, `Color-1…4`, the `system-dark` gradient, and the Aqua, DarkAqua and Tintable icon groups and stacks all have identical digests. Only the flattened per-size PNGs have new digests. When the system renders both builds' icons, they differ by at most 3/255 per channel, which is encoding noise.

**Renders** (this round I rendered through the system icon renderer, so the true `Assets.car` renditions are used, including a real 512 px; the first review had to upscale 256)
- `icon/built_16.png`, `built_32.png`, `built_128.png`, `built_512.png`, `built_1024.png`
- `icon/source_16/32/128/512.png`: owner art resampled for comparison
- Contact sheets on light (#F6F6F6) and dark (#1E1E1E): `icon/sheet_built_actual.png`, `icon/sheet_built_zoomed.png` (16/32 enlarged ×8, nearest-neighbour), `icon/sheet_source_actual.png`, `icon/sheet_source_zoomed.png`
- The DarkAqua variant couldn't be rendered without changing the system appearance, so it isn't pictured. Its layer and stack digests are unchanged from the first review.

**Findings**
- **Fidelity at 128/512**: faithful to Ali's design. Squircle, receipt proportions, fold, zig-zag tear, U-notch and colours all match. Receipt against tile is 11.5:1.
- **16 px**: the receipt reads, but the tray body is rgb(15,68,40) on a tile of rgb(7,56,31), which is **1.18:1**. Only a 1 px rim (1.8–1.9:1) hints at the tray. At actual size it's a pale receipt on a dark green square with a faint band.
- **32 px**: the tray body is again **1.18:1**. The top and bottom rims (2.6:1 and 3.3:1) outline the tray, so it's recognisable up close but weak in a Finder list.
- **Dark backgrounds**: the tile is 1.27:1 against #1E1E1E, so the silhouette depends on the glass edge at small sizes. That's unchanged.
- **Legacy `.icns`**: still only 16, 16@2x, 128 and 128@2x; no 32@1x, 256@1x or 512 slots. macOS 26 uses the `Assets.car` layered icon, which does contain 16–1024. Include the full set so older contexts don't upscale.

**Proposal:** the concrete candidate recorded in PROPOSALS.md ("Small-size icon contrast", update 2026-09-30: `04-tray-front` fill `#10462A` → `#357C51`, optional dark-variant tile lift) is still the right minimal change and still awaits Ali's decision. I have nothing to add or change, so I made no new proposal.
