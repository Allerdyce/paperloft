# Paperloft Receipts: design critique, 2026-09-30

Reviewer: critic (Mac design lead role). Reviewed against the macOS Human Interface Guidelines and the six-line rubric.
Build: QA build `paperloft-qa/build/QADerivedData/Build/Products/QA/Paperloft Receipts.app` (bundle id `app.paperloft.receipts`).
Method: I looked only at the running app, using background computer-use tools (screenshots, AX tree, clicks and background keystrokes). I did not read any source code or tests.

- Launch A (first launch): `-PaperloftQAProfile critic-onboarding -PaperloftStoreMock YES`
- Launch B (populated): `-PaperloftUITestMode YES -PaperloftModel stub -PaperloftStoreMock YES`. The sample library had 4 Inbox items (all flagged "Issue") and 1 filed receipt.
- Appearance was switched with the app's own Settings › General › Theme control (System / Light / Dark). The Mac's system appearance is Light.

Scores: 5 excellent, 4 good, 3 needs work, 2 poor, 1 broken. Every score below 4 comes with a fix.

---

## 1. Top findings (fix these first)

1. **P1 bug: switching Theme from Dark back to System leaves the windows unreadable.** Text comes out white on a white background and dark controls sit on a light window. It happened both times I tried, in both profiles, and was still there after 3 or more seconds. It only cleared when the window was closed and reopened, or became key again. Evidence: `13-…BLANK.jpg`, `14-…BLANK.jpg`, `49-…BLANK-repro2.jpg`, `50-review-inbox-after-dark-to-system-BROKEN.jpg`. Fix: when the theme is System, clear the override everywhere. Set `NSApp.appearance = nil` and clear each window's `appearance`. Don't rely on `.preferredColorScheme(nil)` to revert an explicit `.dark`; that is a known SwiftUI trap. Then force a redraw of the open windows.
2. **Review inbox form polish and controls (Polish 2, HIG 2).** Labels don't line up in one column, pickers and text fields are different widths, the date is typed as an ISO string, the total has no currency formatting, and Currency is a free-text field. Rebuild it as a `Form`/`Grid` with a trailing-aligned label column, a `DatePicker(.field)`, a currency `Picker`, and amounts shown with `.currency` and `.monospacedDigit()`.
3. **Library table (Polish 2, Keyboard 2).** The column headers are static text about 8–10 px off their values. The selection is a faint 1 px outline. The app has no ⌘F. Replace it with a native SwiftUI `Table` (sortable, resizable, right-aligned Total), put `.searchable` in the toolbar, and add Edit › Find (⌘F).
4. **Settings "Turn On" error (Empty/Error 2).** With no watched folder chosen, Turn On shows "Choose the watched folder again to renew access. Watched-folder history is unreadable. Existing documents were preserved." That message is wrong and alarming. Disable Turn On until a folder is chosen, or make it a Toggle that opens the chooser.
5. **Export sheet validation (Empty/Error 2).** Picking Custom dates shows an orange "Enter a valid year or date range." before the user has typed anything, in two `YYYY-MM-DD` text fields. Use two `DatePicker(.field)`s and only show validation after an attempt, under the specific field.
6. **Keyboard reach across the app (Keyboard 2–3).** The menu bar has no Confirm, Remove, Next/Previous receipt, Show Sidebar, Go to Inbox/Library/History, Find or Export. In the Inbox, selecting a row moves focus to the Vendor field, so you can't arrow down through the queue.
7. **Copy.** "1 documents" (plural bug). Quick Look shows the internal file name "payload.pdf". Buttons use ASCII "..." instead of the ellipsis "…". The same things are called "receipts" and "documents", and the export is called both "Tax & Accountant Export" and "Accountant pack". Jargon: "API key", "Rebuild Index", "Renew Original Folder Access…", `{date}_{vendor}_{total}`.
8. **Icon at 16/32 px.** The tray is only 1.18–1.23:1 against the tile, so it disappears at 16 px and is faint at 32 px. See section 4 for the minimal fix and a mock.

### Cross-cutting notes

- **SF Symbols**: every icon I saw was an SF Symbol (sidebar, Help sections, export list, toolbar tabs). No custom bitmaps found. Good.
- **Tabular figures**: money shows as plain proportional text ("12.50", "USD 12.50"). Apply `.monospacedDigit()` and locale currency formatting in the Review form, Library Total column and History.
- **History** (seen, not formally scored): the primary line is a raw path, "2026/Office supplies/2026-01-15_LibraryUXReceipt_12.50.pdf". Lead with merchant, amount and category and move the path to secondary text. The Undo button sits 17 px from the right edge and isn't aligned with the date line. Evidence: `30-history-light.jpg`, `45-history-dark.jpg`, `03-onboarding-history-empty-light.jpg`.
- **Menu bar**: View has only "Enter Full Screen", and File has Import Receipts…, Close, Close All, Import From Device. There's no Go menu or Receipt menu, and Edit has no Find. Every main action should have a menu item with a shortcut.

## 4. Icon review

**Sources compared**
- Owner artwork: `/Users/builder/Factory/paperloft/design/app-icon-source.png` (1254×1254, full-bleed, no alpha): a cream receipt with two text bars and a zig-zag tear, set into a green tray with a U-notch, on deep green (#083921).
- Built icon: `Contents/Resources/AppIcon.icns` (extracted with `iconutil -c iconset`), plus `Assets.car`. `assetutil --info` shows the car holds an Icon Composer layered icon (`01-tray-back`, `02-receipt`, `03-fold`, `04-tray-front`, with Aqua, DarkAqua and Tintable groups).
- Sizes rendered with sips: 16, 32, 128 from the `.icns`. **The `.icns` has no 512 px rendition.** It only contains `icon_16x16`, `icon_16x16@2x`, `icon_128x128` and `icon_128x128@2x`, so `built_512_upscaled.png` is the 256 rendition upscaled with sips. sips and iconutil can't extract the true 512/1024 renditions from `Assets.car`. Owner art was resampled to the same sizes for comparison (`source_*.png`).
- Contact sheets on light (#F6F6F6) and dark (#1E1E1E): `icon/sheet_built_actual.png`, `icon/sheet_built_zoomed.png` (16/32 enlarged ×8, nearest-neighbour), `icon/sheet_source_actual.png`, `icon/sheet_source_zoomed.png`.

**Findings**
- **Fidelity at 128/256/512**: faithful to the owner's design. The squircle mask, receipt proportions, fold, zig-zag tear and U-notch all match. The built tray is glassier and very slightly lighter than the art (tray fill ≈ rgb(30,83,56) against tile rgb(8,57,32), 1.45:1), which helps. The receipt is 11–12:1 against the tile in both versions.
- **16 px: the tray disappears.** Tray pixels are about rgb(17,71,43) on a rgb(6,56,31) tile, a contrast of **1.23:1**. At actual size the icon reads as a dark green square with a pale smudge, and the two text bars blur into a grey-green smear.
- **32 px: the tray is faint.** Body is 1.18:1, and only the 1 px top rim (1.43:1) and the dark notch hint at it. It's recognisable up close but not in a Finder list or the menu bar.
- **Dark backgrounds**: the tile is 1.28:1 against #1E1E1E, so at 16 and 32 px the icon's edge relies on the faint glass rim. It is acceptable, but it adds to the "dark blob" look at small sizes.
- **Legacy `.icns`** lacks the 32@1x, 256@1x and 512 (@1x/@2x) slots. macOS 26 uses the `Assets.car` layered icon, but include the full set so older contexts don't upscale the 256.

**Minimal change that keeps the design recognisable** (mock: `icon/sheet_small_current_vs_proposed.png`, `icon/proposed_16.png`, `icon/proposed_32.png`)
1. **Lighten the tray-front layer** (`04-tray-front`) from about rgb(17,70,42) to about **rgb(53,124,81) / #357C51**. That is ≥2.5:1 against the tile (the mock measures 2.6:1 at 32 px and 3.1:1 at 16 px). Keep the lighter top rim. Colour, shapes and composition stay the same, so the large sizes still read as the owner's design, just with a more legible tray.
2. **16 px only** (hand-tuned slot in the `.icns`, or a small-size variant): remove the two text bars from the receipt so it reads as a clean paper shape instead of a smear.
3. Optional: in the DarkAqua variant, lift the tile a step (about #0C4428) so the silhouette separates from dark backgrounds.

## 5. Not covered

- **Paywall**: not reachable. There's no Upgrade or Pro button anywhere (an AX search for "Upgrade" found nothing). The only Pro gate I saw, Settings › "Watched folder · Pro" › Turn On, showed an access error instead of a paywall, with `-PaperloftStoreMock YES`. Help mentions "Paperloft Pro", and the sidebar says "Samples do not count toward your monthly limit", so a limit or paywall probably exists but has no entry point I could reach in this build.
- **Menu bar extra**: not reachable with the allowed background `app_*` tools, which can't click system menu bar status items, and display-scope control needs an approval nobody can give. Help confirms the extra exists ("the window that opens from the menu bar item").
- **Return/Escape inside sheets, and default-button behaviour**: background keystrokes were refused inside the export sheet.
- **Full Keyboard Access traversal and focus rings**: background Tab produced no visible focus ring in the onboarding, Library and Settings windows, so I couldn't confirm focus order there. I couldn't enable FKA because that's a system setting. Only the Review form's Tab order (Vendor → Date → Total) and list ↓ were verified.
- **System panels**: the library folder chooser, Import Receipts…, Paste Image, Import From Device, Choose Watched Folder… and Choose Destination & Export… were not opened, per instructions.
- **Confirm, Remove, Undo, Delete**: not pressed, so I didn't change the sample data. That means post-filing feedback, Undo from History and Recently Deleted weren't reviewed.
- **Receipt detail** (Library › View / double-click) and the **Recently Deleted** view: not opened.
- **Processing and Duplicates states**: the sample library had 0 of each.
- **True 512/1024 icon renditions**: they live only in `Assets.car` and can't be extracted with sips or iconutil; the 512 view is upscaled from 256.
- **VoiceOver / accessibility labels**: not assessed beyond noting that sidebar and list rows are exposed as AXOutline rows.
