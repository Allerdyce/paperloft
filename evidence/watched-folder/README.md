# Local watched-folder scanner component

API: `WatchedFolderScanner(root:stateURL:minimumStableInterval:)` is an actor. Call `scan()` periodically, persist each candidate's exact bytes and inbox review record durably, then call `acknowledge(candidate)`. Candidates contain a stable token, safe single-component filename, SHA-256 hash, and immutable bytes. The scanner never moves, deletes, renames, or changes watched originals. It does not auto-file or access mailboxes/network. The app must retain the user-granted `LibraryAccess` and enforce Pro. This component does not prove app integration or P4 acceptance.

One nonrecursive root; PDF, PNG, JPEG, HEIC and EML filename extensions are eligible. The document reader remains responsible for format validity. Hidden entries, unsupported extensions and directories are ignored. Eligible symlinks and nonregular files produce issues on every scan. Every directory ancestor opens descriptor-relative with nofollow; traversal-only ancestors use Darwin O_EXEC, listing/state parents use O_RDONLY. The root is pinned and its path identity is checked each scan. Root and state URLs must use physical paths; symbolic-link aliases (including /var) are rejected. Caller may obtain the physical path when resolving the user's explicit folder grant, never untrusted file paths.

Stability requires matching device, inode, size, modification and change timestamps on observations at least two seconds apart by default. Changing observations restart the timer. The subsequent bounded read opens nofollow, validates regular-file identity before and after, and verifies the name still names the same snapshot. It reads at most the observed size plus one sentinel byte, rejecting growth/shrinkage. SHA-256 uses Apple's CryptoKit. Pauses in a writer longer than the stability interval can still yield a valid intermediate version; that is why all intake goes to review and later content changes requeue.

Limits: 1,000 entries per scan, 32 MB per file, 64 MB of newly read file data per scan (plus at most one sentinel byte per read), 64 MB retained pending candidate data. Overflow issues tell the caller to queue pending documents before retrying. Acknowledged unchanged snapshots do not consume the next scan's byte budget; later files can proceed. Observations and caches are limited by entry count. A folder over the entry limit is not fully scanned and must be reduced. Candidates must be acknowledged before a later scan detects deletion/replacement of their source; stale tokens fail clearly and durable inbox dedupe should handle that retry.

History tracks the latest acknowledged hash for each exact filename, bounded to 10,000 names and 4 MB encoded JSON. Returning to an older content version requeues it. History lives outside the watched root; physical ancestry is checked. A separate nofollow regular lock file prevents concurrent scanners sharing history. State is validated on startup and compared before every scan/acknowledgment to detect tampering. Corrupt or changed state fails clearly. Successful acknowledgment writes a private exclusive temporary, synchronizes it, atomically renames it into place, then synchronizes the parent directory before consuming the token. A failed acknowledgment does not mark the document acknowledged in memory. An I/O failure after rename can leave new state on disk; restart reloads it, and the inbox was already durable before acknowledgment by API contract. No history records are silently evicted.

Verification: strict Debug and Release package tests (`swift test --package-path Packages/PaperloftKit [-c release] -Xswiftc -warnings-as-errors`). Nine new synthetic tests cover spaced stability/partial writes, exact bytes/original preservation, acknowledgment/restart/change, repeated symlink/FIFO issues, unsafe paths/corrupt history, permission-denied state writes and retry, state tampering/concurrent scanner exclusion, 64 MB budget fairness, replaced roots/state symlinks, and oversized/entry-count limits. Logs: build/watched-debug.log and build/watched-release.log. Local preflight and protected baseline pass; release prerequisites remain deferred. Final Debug and Release runs each passed 51 tests (8 XCTest plus 43 Swift Testing) with zero warning lines. Independent review remains required.
