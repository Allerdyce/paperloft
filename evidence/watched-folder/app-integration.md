# Watched-folder AppModel integration — local work

Merged the independent App Intents adapter branch normally, preserving process notes and both component histories. Settings adds native folder selection, persistent scoped bookmark, explicit Turn On/Turn Off controls, live status and per-file issues. Production entitlement uses the existing conservative Pro provider. No new launch hook, mailbox access, auto-file, release or upload behavior.

The AppModel owns the folder grant while its actor scanner runs. Polling is serialized at three-second intervals; scanner stability remains two seconds. Each scan and delivery rechecks entitlement, enabled state and the active generation. Disable cancels and awaits the polling task before dropping its scanner/grant. Configuration generations ensure an old disable/install continuation cannot clear a newer scanner; overlapping stops share the pending task wait. If Pro is unavailable, scanning pauses without consuming candidates. Startup renews the stored bookmark; stale/unavailable grants show a renewal message.

Candidate bytes are copied into a unique app-owned Watched-Imports directory. Large input copying and ledger loading/validation/encoding/writing run off the main actor. The small inbox metadata commit stays synchronous and uses current items after the copy returns, preserving edits made during copying. The file, directory hierarchy and inbox commit are synchronized before acknowledgment. Originals are never moved. Every item enters ordinary review. EML candidates are explicitly left unacknowledged because this branch does not yet contain the Mail app-intake integration; Settings and per-file messages expose that limitation.

Crash/retry identity is SHA-256(folder physical path + NUL + filename), with latest content hash and a monotonic delivery sequence. The app writes delivery proof into the inbox item in the same atomic inbox commit, then writes a durable separate ledger, then acknowledges the scanner. If the ledger fails after inbox commit, startup or retry recovers the proof from the existing item instead of importing it again. Before filing removes a watched inbox item, its proof must be secured; set-aside retains proof. New sample libraries retain inbox entries as set-aside, and ledger history is independent of library selection. Older items cannot overwrite newer proofs because sequences only advance. A→B→A content versions produce three deliveries, matching scanner latest-content semantics.

The delivery ledger is bounded to 25,000 source identities and 8 MB encoded state; reads are bounded and reject symlink/nonregular/oversize inputs. Corrupt ledger startup fails before inbox changes. No silent eviction. The scanner's separate 10,000-filename/4 MB history bounds continue to apply.

Nine new actual-AppModel functional tests exercise exact copied bytes/original preservation/review status, scanner acknowledgment failure plus restart/set-aside, inbox-commit-before-ledger-failure recovery, changed and reverted content, free/revoked Pro and disable behavior, unsupported Mail remaining pending, and failed inbox commit with retry, and oversized ledger preserving the existing inbox, and overlapping configuration changes, and broken ledger symlink rejection. A separate worst-case measurement test samples main-actor availability at 10 ms intervals during startup and three 32 MB deliveries with a near-capacity ledger; Debug and optimized Release each passed this measurement without warnings. Complete delivery wall times were 132–134 ms Debug and 125–130 ms Release; maximum main-actor heartbeat gaps were 12.99 ms and 13.51 ms respectively. Results: build/WatchedHeartbeatDebug.xcresult and build/WatchedHeartbeatRelease.xcresult; logs build/watched-heartbeat-{debug,release}.log. This is a scoped main-actor availability measurement, not a full-app frame-time or P6 acceptance claim. Tests use ordinary storage/preferences/entitlement/path injection and no added launch hooks. Strict Debug and optimized Release (`ENABLE_TESTABILITY=YES`) each passed all 16 adapter/operation tests with zero warning lines: build/WatchedAdapterDebug4.xcresult and build/WatchedAdapterRelease2.xcresult; logs build/watched-adapter-{debug,release}.log. The separate maximum-size heartbeat check also passed in the coordinated quiet window. Plain Release app build also passed without warnings (build/watched-app-release.log), and the protected baseline passed (build/watched-final-baseline.log). Native panel/bookmark UI interaction remains unverified here. StoreKit default remains false until commerce integration; full P4 and release gates are not claimed.

### Native lifecycle result

The independent native XCUITest route passed on the fourth run: `build/WatchedNativeUI4.xcresult`, `build/watched-native-ui4.log`, one test in 65.59 seconds, zero compiler-warning lines. It uses only the existing sample-library, stub-model and Store-mock arguments. The test creates its own PDF with Apple graphics APIs and writes only runner-owned temporary storage; it selects that folder through the real directory panel. It verifies first-file review and unchanged bytes, Turn Off preventing a second input for eight seconds, Turn On importing it, process termination/relaunch, restored bookmark and enabled controls, a newly created third input arriving without reselecting the folder, and exactly one visible inbox entry per first/second input. It turns watching off and terminates the app at the end. Screenshots are `screenshots/native-review.png` and `screenshots/bookmark-restored.png`.

Earlier runs are retained: UI1 failed before app launch because the sandboxed UI runner could not create a folder under repository build; this was corrected to runner-owned temporary test storage without changing app sandboxing. UI2 failed because a Window-menu lookup also matched Apple Recent Items entries; the test now scopes that query to Window. UI3 reached bookmark restoration but XCTest rejected the long temporary path as an identifier over 128 characters; the same exact path is now asserted with an explicit value/label predicate. No product assertion was removed and no product source was changed for these corrections.

The test explicitly opens the existing public Window > Paperloft Receipts command when macOS starts windowless. It does not certify launch window restoration or menu-bar Open Inbox behavior, which are separate work. Native folder/bookmark lifecycle is now verified in the Debug mock-entitlement test environment; real StoreKit entitlement, Mail watch integration and whole-phase/distribution acceptance remain outside this result.
