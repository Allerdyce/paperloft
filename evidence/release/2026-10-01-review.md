# Release check: Paperloft Receipts, 2026-10-01

Checker: `release_checker`. Branch `run/1`. HEAD is `0fce214`; the product code is the same as merge `93da86b` (`git diff --stat 93da86b 0fce214` touches only README.md, REPORT.md and one evidence file).

## Summary

**39 PASS, 5 FAIL, 5 PENDING** (49 items).

**App Review blockers.** These three would likely cause a rejection or a refused upload:

1. **The App Store metadata has no Terms of Use (EULA) link.** Apple requires this link for auto-renewable subscriptions (Guideline 3.1.2). The paywall itself is fine.
2. **The main app's privacy manifest declares no required-reason APIs.** The app uses UserDefaults and file-timestamp APIs. The Share extension declares File Timestamp for the same shared code; the main app declares nothing.
3. **No distribution configuration exists that turns on the App Group.** With the project defaults, the Share extension ships switched off and shows "Sharing needs a signed Paperloft build". The description advertises "share from Finder".

**Fix before submission.** These two are not likely rejection reasons on their own:

4. **The live `/receipts/` page has three claims the build doesn't support.** They are "Files itself", "Undo any batch … in one step", and a JPG shown being filed as a PDF. The unpublished branch fixes only the first.
5. **The version numbers don't match.** The build is 1.1. The listing draft, SPEC and AC-19 all say 1.0.

**PENDING items** all wait on App Store Connect, which isn't available until the EvidencePair LLC membership is active. They are the archive and processed build, the metadata entry, the screenshot upload, the two products, and the copyright field. Everything that can be prepared for them is ready in `release/`.
